# Platform Context Pack  (SUPER level)

> **What this is.** The single, top-level source of truth that every service inherits.
> Each service's `CLAUDE.md` imports this file (`@../platform-context-pack.md`) instead of
> copying it. Fix a pattern *here once* and all ~50 apps inherit it. **Do not fork this into
> per-service files.** If something is true for >1 service, it belongs here, not there.
>
> **Owner:** Platform team · **Freshness SLO:** reviewed monthly, regenerated by
> `platform-agent.md` · **Status legend:** 🟢 Golden (the paved road, default) ·
> 🟡 Recommended · 🔵 Emerging (proven by ≥1 team, not yet default).

---

## 0. The estate (orientation)

- ~30 internal microservices + ~20 cross-platform applications outside the platform boundary.
- **Seams = where entropy hurts most:** shared contracts, auth, the data plane, and every
  call that crosses the platform boundary. Treat seams as high-blast-radius (see Autonomy).
- The paved road below exists so that an agent (or human) can work on *one* service without
  holding the whole estate in context. Deviating from it is allowed but must be *justified
  and recorded* in the service's `CLAUDE.md` — silent divergence is the thing we are fighting.

## 1. Golden patterns (the paved road)

| Concern | 🟢 Golden default | Notes |
|---|---|---|
| **Service shape** | Generated from the golden service template | New service ⇒ scaffold, never hand-roll |
| **API / contracts** | Contract-first (OpenAPI/proto checked into repo); breaking changes are versioned | CI enforces contract conformance |
| **Auth** | Platform identity at the edge; service-to-service via signed tokens | Never invent auth at the service |
| **Error model** | One canonical error envelope `{code, message, retriable, correlationId}` | No bespoke error shapes |
| **Idempotency** | All mutating cross-service calls carry an idempotency key | Mandatory at the seams |
| **Observability** | Structured logs + traces + the standard RED/USE metrics, correlationId propagated | Emitted by the shared lib, not hand-wired |
| **Eventing** | Schema-registered events; at-least-once; consumers idempotent | Contracts live in the registry |
| **Data** | One service owns its store; no cross-service DB reads | Cross-service = via API/event only |
| **Config & secrets** | 12-factor; secrets from the platform secret store, never in code/env files | CI scans for leaks |
| **Deploy** | Standard pipeline; progressive rollout + health gates | Rollback is one command |

## 2. Cross-cutting invariants (must NEVER break)

1. A service owns its data; others reach it only through its published contract.
2. Money / ledger / state mutations are idempotent and auditable end-to-end.
3. Every request carries a `correlationId` that propagates across every hop.
4. No secret in source, logs, or traces.
5. A breaking contract change ships as a new version — never mutate v1 in place.

## 3. The "why" (the decisions behind the rules)

- **Contract-first** because the seams are where 50 teams collide; the contract is the only
  thing that lets them move independently.
- **One store per service** because shared databases are how a microservice estate quietly
  becomes a distributed monolith.
- **Idempotency everywhere at the seams** because at-least-once delivery + retries are the
  default reality, and the only safe response is idempotent consumers.

## 4. Autonomy map (how much an agent may do unattended)

| Surface | Autonomy | Rule |
|---|---|---|
| Leaf service, ≥X% coverage, no seam impact | 🟢 High | Agent may open PRs unattended |
| Touches a published contract / shared event | 🟡 Medium | Human review required |
| Auth, money/ledger, the data plane, cross-boundary apps | 🔴 Low | Human-in-the-loop, mandatory review |

## 5. Glossary

- **Seam** — any boundary a request crosses (service↔service, platform↔external).
- **Paved road** — the Golden defaults above; the path of least resistance.
- **Distillation** — promoting a proven team pattern into this pack (see `platform-agent.md`).
